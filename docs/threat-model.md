# Local-installation and optional Gemini threat model

Scope: one trusted OS user and one installation on loopback. Protect private audio, authored transcripts, review state, and the local bearer token from accidental disclosure and unrelated websites. Default fixture mode is offline; optional live uploads explicitly send audio and a subsequent transcript to Gemini. This is not hosted security acceptance.

| Boundary | Control and checked behavior | Residual risk |
|---|---|---|
| Untrusted file to API | Stream cap 24 MiB; 20-second upload deadline; PCM WAV signature/stdlib parsing; bounded rate/channels/sample width/frame count/duration; truncated data rejected | Eight simultaneous API requests can consume memory; compressed-format decoder sandboxing is deferred because compressed inputs are rejected |
| Browser to private records | Required random bearer token; constant-time comparison; explicit local Host/Origin allowlists; loopback bindings; no token in URL/bundle; private audio fetched with auth | A process running as the same OS user can read token/database/audio/key; sessionStorage is vulnerable to an origin-level XSS |
| Recording/item references | UUID filenames and IDs; SQL parameters; item updates scoped by recording; version-based edit conflicts; audio/export require token | No cross-user/tenant isolation is claimed; everybody with this installation token owns its library |
| Fixture to model-like claims | Exact whole-file SHA-256 gate; explicit fixture UI; unknown audio yields failed/no transcript; source/version labels in export | No live quality evidence; authored suggestions can still be edited incorrectly |
| Review to export | Reviewed items only; JSON attachment with constant filename; text rendered as React text/textarea; no tools/contact execution | Downloaded JSON is private data; downstream tools must treat its content as data |
| Job to storage | PostgreSQL durable state; single-worker advisory lock; state guards/row locks; atomic ready/results; restart recovery; cancellation/deletion checks | No HA/supervisor; infrastructure errors stop the worker and require restart; orphan cleanup is offline/manual |
| Retention | Generated WAV files 0600; generated token 0600; ignored data; explicit delete removes WAV and cascades reviews | Parent directory permissions, OS backups, swap, browser downloads, and DB-volume snapshots are outside secure-erasure guarantees |

Validation directly uses Python's bounded uncompressed PCM reader; no external decoder, shell interpolation of filenames, user-controlled network destination, or model tool call exists. The optional Gemini adapter uses a fixed HTTPS endpoint, no redirects/proxy environment, bounded payload/output and timeouts, stateless `store=false`, no retries or fallbacks, and sanitized error strings. `store=false` controls interaction state; it is not a promise about all provider data usage/retention. Free-tier data handling and billing-disabled configuration must be reviewed before enabling external sends. The player may decode already validated WAVs in the browser. Imported text cannot execute code. The development Vite server is not a production web server and must remain loopback.

Compose database credentials are a documented local development default, and Redis has no password; neither is exposed outside loopback. Set installation-specific credentials in `.env` before using sensitive local data. The server token is generated per checkout, never a shared committed default. Dependency versions are locked. npm and Python dependency audits were run and findings fixed (see verification); these are point-in-time checks, not a full security or license audit. Pending before publication/hosting: container-image scans, third-party license inventory, broader browser/accessibility verification, deployment identity/TLS/quotas, live quality/second-provider acceptance, provider data-usage review for sensitive audio, and compressed decoder isolation if added. No real private audio was sent during implementation.
